2. STRUCTURED DATA SOURCES & STORAGE
--------------------------------------------------------------------------------
The knowledge base relies on authoritative database collections:
  - `timetables`: Schema validated against `backend/app/schemas/timetable.py`.
    Stores active and historical versions of class schedules.
  - `mess_menus`: Schema validated against `backend/app/schemas/mess.py`.
    Stores weekly meal schedules and special menus.
  - `campus_locations`: Schema validated against `backend/app/schemas/map.py`.
    Stores geospatial nodes, edges, codes, and accessibility metadata.
  - `university_policies`: Structured registry in `seed_data.py` storing verified
    clauses, ordinance references, and official contact officers.


3. SOURCE PRIORITY POLICY
--------------------------------------------------------------------------------
When answering queries, NextCampus AI enforces a strict priority hierarchy:

  Rank 1: Currently Published Database Records (Active Version)
          - Timetable records with `is_published: true`.
          - Mess menus marked as active for the specified day/date.
          - These records strictly supersede any LLM parametric knowledge.

  Rank 2: Official Approved University Ordinances & Documents
          - Verified attendance rules, library guidelines, and exam calendars.
          - Sourced directly from verified institutional policies.

  Rank 3: General Educational & Academic Explanations
          - General programming concepts, mathematical principles, study tips.
          - Handled via general LLM knowledge ONLY when no institutional policy applies.

Conflict Resolution:
If conflicting schedules or documents are detected, the system discloses the ambiguity
and reports the version timestamp rather than silently guessing.


4. DATA FRESHNESS & CACHING POLICY
--------------------------------------------------------------------------------
- Timezone Sensitivity: All dates and times are resolved against `Asia/Kolkata`
  using the server-side system clock.
- Immediate Cache Invalidation:
  When an administrator publishes a new timetable or mess menu version, any active
  caches are instantly invalidated. The newly published record is immediately
  retrievable on the subsequent request turn.


5. MISSING DATA & ANTI-HALLUCINATION BEHAVIOR
--------------------------------------------------------------------------------
NextCampus AI never fabricates or hallucinates university facts.
- If a timetable for an unknown section (e.g., "Civil Engineering Section Z") is requested:
  -> System responds: "The timetable for Civil Engineering Section Z is not available
     in the current university records."
- If a meal item is unrecorded for a specific slot:
  -> System responds: "The menu for this meal has not been published yet."
- If a student asks "When is my next class?" but has no active timetable:
  -> System prompts the student to specify their department, semester, and section.


6. ADMINISTRATIVE KNOWLEDGE UPDATES
--------------------------------------------------------------------------------
University knowledge is updated through two safe mechanisms:
1. Interactive Administrator Updates Modal (`AdminUpdatesModal.jsx`):
   - Administrators upload Excel, CSV, or PDF schedules.
   - The system parses, validates, and generates a visual preview with conflict detection.
   - On explicit confirmation, records are atomically committed with version incrementation.
2. Direct API Ingestion:
   - Secured REST endpoints with role enforcement (`/api/v1/timetable/publish`,
     `/api/v1/mess/publish`).
